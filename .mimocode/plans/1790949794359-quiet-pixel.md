# Plan: Admin multi-site registration + worker GPS check-in

## Locked decisions (user)

| Topic | Choice |
|-------|--------|
| **Map / search service** | **Google Places + Geocoding** (Google Maps Platform) |
| **Worker site choice** | **Any active site** — no per-worker assignment |
| **Default office** | **Keep HQ as default** — existing `OFFICE_*` path unchanged when no site selected |

## Goal

Admins register remote **project sites** (name + address + lat/lng + radius) on a Google map. Workers pick any **active** site (or HQ) before check-in; server verifies GPS against that site’s geofence. HQ remains the default path.

## Stack

| Layer | Choice |
|-------|--------|
| **Admin map UI** | **Google Maps JavaScript API** + **Places Autocomplete** (search-as-you-type) + draggable marker |
| **Reverse geocode** (optional pin-drop address) | **Google Geocoding API** |
| **Key** | `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` — browser key, restricted to Places + Maps JavaScript + Geocoding; HTTP referrer restricted to Vercel prod + `localhost` |
| **Billing** | Google Cloud billing required. Maps Platform gives **~$200/month free credit** — enough for occasional admin search, not free forever. Admin-only traffic keeps cost low. |
| **DB** | Neon Postgres `sites` table (existing stack) |
| **Worker map** | **None** — native `<select>` only (no Google on worker PWA) |

**User setup before admin map works:**
1. Google Cloud project → billing enabled  
2. Enable: **Places API (New)**, **Maps JavaScript API**, **Geocoding API**  
3. Browser API key with referrer restrictions  
4. Set Vercel env `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` → **Redeploy**  
5. Agent must **never** commit the key; it is public-by-design (client) but still env-only on Vercel

## Product rules

1. **HQ default:** no `siteId` → existing office IP / HQ GPS path (`OFFICE_*`). Welcome/goodbye keep office name/city.
2. **Any active site:** worker may select any row with `active = true`. No `worker_sites` table in v1.
3. **Site check-in:** if `siteId` sent → load active site → Haversine(gps, site.lat/lng) ≤ `site.radius_m` → method `site_gps`, store `site_id`. **Do not** accept HQ IP match when a remote site is selected.
4. **Missing/inactive site:** 422 `SITE_UNAVAILABLE` (clear message; do not silently fall back to HQ).
5. **Admin gate:** Google SSO + `requireAdmin()` / `ADMIN_EMAILS`.
6. **GPS still mandatory** on client for all check-in/out.

## Data model

Migration `db/migrations/0004_project_sites.sql` + update `db/schema.sql`:

```sql
CREATE TABLE IF NOT EXISTS sites (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name          TEXT NOT NULL,
  address       TEXT,
  lat           DOUBLE PRECISION NOT NULL,
  lng           DOUBLE PRECISION NOT NULL,
  radius_m      DOUBLE PRECISION NOT NULL DEFAULT 100,
  active        BOOLEAN NOT NULL DEFAULT TRUE,
  created_by    TEXT,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

ALTER TABLE attendance_days
  ADD COLUMN IF NOT EXISTS site_id UUID REFERENCES sites(id) ON DELETE SET NULL;

ALTER TABLE attendance_events
  ADD COLUMN IF NOT EXISTS site_id UUID REFERENCES sites(id) ON DELETE SET NULL;

CREATE INDEX IF NOT EXISTS sites_active_idx ON sites (active) WHERE active;
```

`check_in_method` / `check_out_method` / `verification_method` allow `office_ip` | `gps` | **`site_gps`**.

## API

| Method | Path | Auth | Purpose |
|--------|------|------|---------|
| GET | `/api/admin/sites` | admin | List all sites |
| POST | `/api/admin/sites` | admin | Create site |
| PATCH | `/api/admin/sites/[id]` | admin | Update name/address/coords/radius/active |
| DELETE | `/api/admin/sites/[id]` | admin | Soft-delete preferred: set `active=false` (hard delete optional) |
| GET | `/api/sites` | worker | Active sites for picker (`[{id,name,address,lat,lng,radius_m}]`) |

Check-in/check-out body: `{ gps, siteId?: string | null }`.

`lib/verification.ts` extended:

```ts
// siteId path: load site → haversine ≤ radius_m → site_gps + site_id
// no siteId: existing office_ip / HQ gps path
// siteId provided but inactive/missing → fail SITE_UNAVAILABLE
```

## Admin UI (`/admin/sites`)

- **AdminNav** item: **Sites** → `/admin/sites`
- Client component (Google Maps loaded dynamically — no SSR)
- List table: name, address, radius, lat/lng, active toggle
- Form / panel:
  - Name (required), address (from Places or manual)
  - **Places Autocomplete** search → map flies to result
  - Draggable marker + map click → update lat/lng
  - Reverse geocode (optional) to fill address on pin drop
  - Radius number/slider (default **100** m)
  - Save / Deactivate
- If `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` missing → clear admin panel message (SetupRequired-style), not a blank map crash

## Worker UI (`CheckInForm` on `/` hub)

- After signed-in card: **Work location** native `<select>`
  - Option 0 (default): `Head office (default)` — no `siteId`
  - Options: active site names from `GET /api/sites`
- Check In / Check Out send `siteId` only when non-HQ selected
- Status copy:
  - HQ: existing office messages / distance “from office”
  - Site: `Welcome to {siteName}!` / distance “from {siteName}”
- `/check-in` stays secondary; **one picker on the hub** to avoid dual UI drift

2. Admin: create site via Places search + pin → row in `sites`  
3. Admin UI works with valid key; missing key shows setup message

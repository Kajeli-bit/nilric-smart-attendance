# Google SSO credential setup — Nilric Smart Attendance

## Answer

**Yes** — the steps you pasted are the correct core flow (create a **Web application** OAuth 2.0 client). For this app you also need the **OAuth consent screen**, **redirect URIs**, **JavaScript origins**, and (if Testing mode) **test users**. Without those, Google sign-in will fail even with a Client ID/Secret.

This app uses **Auth.js / NextAuth v5** with the Google provider (`lib/auth.ts`). It reads:

| Env var | Source |
|---------|--------|
| `GOOGLE_CLIENT_ID` | Client ID from Google Cloud |
| `GOOGLE_CLIENT_SECRET` | Client secret from Google Cloud |
| `AUTH_SECRET` | `openssl rand -base64 32` (not from Google) |

Callback path (NextAuth default):

```
/api/auth/callback/google
```

## Complete Google Cloud setup (checklist)

### 1. Create / select a project
1. Open [Google Cloud Console](https://console.cloud.google.com/).
2. Create a new project (e.g. `nilric-attendance`) or select an existing one.

### 2. Configure OAuth consent screen (required first)
1. **APIs & Services → OAuth consent screen**
2. User type: **External** (unless you use Google Workspace and want Internal)
3. App information:
   - App name: `Nilric Smart Attendance`
   - User support email: your Google account
   - Developer contact: your email
4. Scopes: add
   - `openid`
   - `email`
   - `profile`
   (Auth.js Google provider uses these by default — no extra APIs required)
5. Test users (if status is **Testing**):
   - Add every Google account that will sign in (workers + admins)
   - Production later: publish the app, or keep adding users while Testing
6. Save.

### 3. Create the OAuth client (your steps, completed)
1. **APIs & Services → Credentials → Create Credentials → OAuth client ID**
2. Application type: **Web application**
3. Name: e.g. `nilric-web`
4. **Authorized JavaScript origins** (required for browser sign-in):

   | Environment | Origin |
   |-------------|--------|
   | Netlify production | `https://YOUR-SITE.netlify.app` |
   | Netlify preview | `https://deploy-preview-N--YOUR-SITE.netlify.app` (each preview you care about) |
   | Local Netlify | `http://localhost:8888` |

5. **Authorized redirect URIs** (required — must match NextAuth exactly):

   | Environment | Redirect URI |
   |-------------|--------------|
   | Netlify production | `https://YOUR-SITE.netlify.app/api/auth/callback/google` |
   | Local Netlify | `http://localhost:8888/api/auth/callback/google` |
   | Custom domain | `https://your-domain.com/api/auth/callback/google` |

6. Click **Create**.
7. Copy:
   - **Client ID**
   - **Client Secret**

> Note: You do **not** need to enable a separate “Google+” API. OpenID Connect / basic profile is enough for email + name + avatar.

### 4. Put values into the app
**Netlify → Site settings → Environment variables:**

```
GOOGLE_CLIENT_ID=<Client ID>
GOOGLE_CLIENT_SECRET=<Client Secret>
AUTH_SECRET=<openssl rand -base64 32>
ADMIN_EMAILS=you@gmail.com
OFFICE_NAME=Nilric HQ
OFFICE_CITY=Dar es Salaam
OFFICE_PUBLIC_IP=<static office IP>
OFFICE_LAT=-6.7924
OFFICE_LNG=39.2086
OFFICE_RADIUS_METERS=100
OFFICE_TIMEZONE=Africa/Dar_es_Salaam
```

**Local `.env`:** same values; local redirect must be `http://localhost:8888/api/auth/callback/google`.

### 5. Redeploy
Env var changes on Netlify need a **redeploy** (or manual env refresh + redeploy) before `signIn("google")` works.

## Common failures

| Symptom | Cause |
|---------|--------|
| `redirect_uri_mismatch` | Redirect URI missing or wrong path (`/api/auth/callback/google`) |
| `access_blocked` / app not verified | User not on **Test users** list while consent is Testing |
| `invalid_client` | Wrong Client ID/Secret or env not applied / site not redeployed |
| Sign-in works but admin blocked | Email not in `ADMIN_EMAILS` |
| Works on deploy preview only | Production origin not in JavaScript origins / redirect URIs |

## Verification

1. Local: `npx netlify dev` → open `http://localhost:8888/check-in` → **Sign in with Google**.
2. After Google consent, app should land back on `/check-in` with the user’s email shown.
3. Deny location → check-in must **not** proceed.
4. Allow location near office coords → welcome message with office name + city.
5. Admin: sign in with an email from `ADMIN_EMAILS` → `/admin` loads workers/reports.
6. Non-admin Google user → admin APIs return `403 FORBIDDEN`.

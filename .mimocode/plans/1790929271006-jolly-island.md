# Nilric Smart Attendance — Implementation Plan

Greenfield **Next.js App Router PWA** on **Netlify** + **Netlify Database (Postgres)**. Workers check in/out online; office Wi-Fi IP is the primary verification layer, GPS geofence is the fallback. Full admin dashboard for workers + reports.

---

## Confirmed decisions

| Topic | Choice |
|-------|--------|
| Database | **Netlify Database (Postgres)** via `@netlify/database` |
| Worker identity | Employee code + name (auto-create on first successful check-in) |
| Attendance | Check-in **and** check-out |
| Admin | Full: workers CRUD + reports + CSV export |
| Office config | Netlify **env vars** |
| PWA | **Serwist** (`@serwist/next` webpack path) |
| Offline | **Online only** — no offline queue |

## Database schema

**File:** `netlify/database/migrations/0001_create_core_tables.sql`

```sql
CREATE TABLE workers (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  employee_code TEXT NOT NULL UNIQUE,
  name          TEXT NOT NULL,
  active        BOOLEAN NOT NULL DEFAULT TRUE,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE attendance_days (
  id                   UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  worker_id            UUID NOT NULL REFERENCES workers(id) ON DELETE CASCADE,
  attendance_day       DATE NOT NULL,          -- office-local calendar day
  check_in_at          TIMESTAMPTZ NOT NULL,
  check_in_method      TEXT NOT NULL,          -- 'office_ip' | 'gps'
  check_in_ip          TEXT,
  check_in_lat         DOUBLE PRECISION,
  check_in_lng         DOUBLE PRECISION,
  check_in_distance_m  DOUBLE PRECISION,
  check_out_at         TIMESTAMPTZ,
  check_out_method     TEXT,
  check_out_ip         TEXT,
  check_out_lat        DOUBLE PRECISION,
  check_out_lng        DOUBLE PRECISION,
  check_out_distance_m DOUBLE PRECISION,
  created_at           TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at           TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (worker_id, attendance_day)
);

CREATE INDEX attendance_days_day_idx    ON attendance_days (attendance_day);
CREATE INDEX attendance_days_worker_idx ON attendance_days (worker_id, attendance_day);

CREATE TABLE attendance_events (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  attendance_day_id   UUID NOT NULL REFERENCES attendance_days(id) ON DELETE CASCADE,
  worker_id           UUID NOT NULL REFERENCES workers(id) ON DELETE CASCADE,
  event_type          TEXT NOT NULL,           -- 'check_in' | 'check_out'
  occurred_at         TIMESTAMPTZ NOT NULL,
  verification_method TEXT NOT NULL,           -- 'office_ip' | 'gps'
  client_ip           TEXT,
  lat                 DOUBLE PRECISION,
  lng                 DOUBLE PRECISION,
  distance_m          DOUBLE PRECISION,
  created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX attendance_events_worker_time_idx ON attendance_events (worker_id, occurred_at DESC);
CREATE INDEX attendance_events_time_idx         ON attendance_events (occurred_at DESC);
```

**Rules**
- `attendance_day` = calendar day in **office timezone** (not UTC).
- Timestamps stored as UTC `TIMESTAMPTZ`.
- Double check-in / check-out blocked by unique key + state checks.
- Race guard: `INSERT ... ON CONFLICT (worker_id, attendance_day) DO NOTHING` then re-read.
- Auto-create worker **only after successful verification** (no junk rows from failed attempts).

## Dual-layer verification

**Files:** `lib/verification.ts`, `lib/geo.ts`, `lib/env.ts`, `lib/attendance-day.ts`

### Client IP (Netlify)

```ts
export function getClientIp(headers: Headers): string | null {
  const nf = headers.get("x-nf-client-connection-ip");
  if (nf?.trim()) return nf.trim();
  const xff = headers.get("x-forwarded-for");
  if (!xff) return null;
  return xff.split(",")[0]?.trim() || null;
}
```

### Algorithm

```
Layer 1 — office Wi-Fi IP
  if OFFICE_PUBLIC_IP set AND clientIp === OFFICE_PUBLIC_IP:
    success via "office_ip"  (GPS not required)

Layer 2 — GPS geofence fallback
  if gps.lat/lng present AND office lat/lng set AND radius > 0:
    d = haversine(gps, office)
    if d <= OFFICE_RADIUS_METERS:
      success via "gps", distance = d

else: fail 422 NOT_VERIFIED
```

### Haversine (`lib/geo.ts`)

```ts
export function haversineMeters(lat1, lng1, lat2, lng2): number {
  const R = 6371000;
  const toRad = (d) => (d * Math.PI) / 180;
  const dLat = toRad(lat2 - lat1);
  const dLng = toRad(lng2 - lng1);
  const a = Math.sin(dLat/2)**2 +
            Math.cos(toRad(lat1))*Math.cos(toRad(lat2))*Math.sin(dLng/2)**2;
  return 2 * R * Math.asin(Math.sqrt(a));
}
```

### Edge cases

| Case | Behavior |
|------|----------|
| IP header missing | Skip Layer 1; require GPS or fail |
| IP matches, GPS denied | **Success** via office_ip |
| GPS outside radius | Fail even if IP wrong |
| Failed verification | Do not auto-create worker; do not write attendance |
| Local `netlify dev` | No Netlify IP header — set `OFFICE_PUBLIC_IP=127.0.0.1` for Layer-1 tests, or test GPS path |
| GPS spoofing | Residual risk; IP layer is stronger when office IP is static |
| Office IP not static | Layer 1 permanently broken — ops prerequisite |

## API design

### Worker

#### `POST /api/check-in`

Request:
```json
{
  "employeeCode": "NIL-001",
  "name": "Amina Juma",
  "gps": { "lat": -6.7925, "lng": 39.2087 }
}
```

Success `201`:
```json
{
  "ok": true,
  "action": "check_in",
  "worker": { "id": "…", "employeeCode": "NIL-001", "name": "Amina Juma" },
  "attendance": {
    "attendanceDay": "2026-03-04",
    "checkInAt": "2026-03-04T06:15:22.000Z",
    "method": "office_ip",
    "distanceMeters": null
  }
}
```

Errors:
| Status | `error` | When |
|--------|---------|------|
| 400 | `INVALID_INPUT` | Missing code/name |
| 422 | `NOT_VERIFIED` | Dual-layer failed |
| 409 | `ALREADY_CHECKED_IN` | Already checked in today without check-out |
| 409 | `INACTIVE_WORKER` | Worker deactivated |
| 500 | `INTERNAL` | DB/unexpected |

Worker resolution: lookup by `employee_code` (trim, case-insensitive). Missing → auto-create. Exists + different name → update name only on successful verification.

#### `POST /api/check-out`

Request: `{ "employeeCode": "NIL-001", "gps": { "lat": …, "lng": … } }`
`name` optional on check-out.

Success `200`: `action: "check_out"` with `checkOutAt`, `method`, `distanceMeters`.

Errors: `422 NOT_VERIFIED`, `409 NOT_CHECKED_IN`, `409 ALREADY_CHECKED_OUT`, `404 WORKER_NOT_FOUND`.

### Admin (cookie-protected)

Auth: `ADMIN_PASSWORD` env + httpOnly cookie `admin_session`. Login uses timing-safe compare. All `/api/admin/*` except login/logout require cookie → else `401 UNAUTHORIZED`.

| Method | Path | Purpose |
|--------|------|---------|
| POST | `/api/admin/login` | Set cookie |
| POST | `/api/admin/logout` | Clear cookie |
| GET | `/api/admin/workers` | List (`?q=&active=`) |
| POST | `/api/admin/workers` | Create |
| GET | `/api/admin/workers/:id` | Detail |
| PATCH | `/api/admin/workers/:id` | Edit |
| POST | `/api/admin/workers/:id/deactivate` | Soft deactivate |
| POST | `/api/admin/workers/:id/activate` | Reactivate |
| GET | `/api/admin/attendance` | Report (`?from=&to=&workerId=`) |
| GET | `/api/admin/attendance.csv` | CSV export |

Report row: worker code/name, `attendanceDay`, `checkInAt`, `checkOutAt`, methods, distances, `workedMinutes`.

CSV columns: `employee_code,name,attendance_day,check_in_at,check_out_at,check_in_method,check_out_method,check_in_distance_m,check_out_distance_m,worked_minutes`.
**Sanitize cells** starting with `= + - @` (CSV formula injection).

## Worker UI (`/check-in`)

- Inputs: employee code, name (name required only for first check-in / optional after lookup)
- Two buttons: **Check In** / **Check Out**
- On click: request geolocation (`enableHighAccuracy: true`) only if not already known good; also send GPS when available
- Online gate: disable submit when `navigator.onLine === false`
- Status states: locating → verifying → success / error with method + distance
- `IosInstallHint`: detect iOS Safari non-standalone → "Share → Add to Home Screen"
- Android: use `beforeinstallprompt` banner when available

Geolocation request: HTTPS only (Netlify provides), user gesture only, show accuracy clearly.

## Verification plan

### Local (`netlify dev`)
1. Migrations apply; three tables exist.
2. Layer 1: `curl -X POST localhost:8888/api/check-in -H 'x-nf-client-connection-ip: 127.0.0.1' -H 'Content-Type: application/json' -d '{"employeeCode":"NIL-001","name":"Test"}'` with `OFFICE_PUBLIC_IP=127.0.0.1` → success.
3. Layer 2 GPS: omit IP header; send coords near (-6.7925, 39.2087) vs far → near succeeds, far fails.
4. Double check-in → `409 ALREADY_CHECKED_IN`; check-out then re-check-in OK.
5. Check-out without check-in → `409 NOT_CHECKED_IN`.
6. Deactivated worker → `409 INACTIVE_WORKER`.
7. Admin: wrong/right password; workers CRUD; report filters; CSV headers correct.
8. Offline: UI blocks submit; no fake success.
9. Build succeeds; `public/sw.js` generated.

### Deployed
1. Preview deploy: migrations run; smoke APIs.
2. On office Wi-Fi: check-in via IP layer (deny geolocation permission to prove Layer 1).
3. On cellular outside radius: rejection.
4. Boundary GPS ~90m vs ~150m.
5. Install PWA on Android; iOS Add to Home Screen; standalone chrome.
6. Timezone edge: event after 23:50 local lands on correct `attendance_day`.
7. Confirm `x-nf-client-connection-ip` appears in function logs on real traffic.

## Risks / ops notes

- **Office public IP must be static.** Dynamic ISP egress breaks Layer 1.
- **GPS is spoofable.** Dual-layer reduces fraud; admin sees method + distance.
- **Netlify Database is credit-based** (storage free until July 1, 2026). Monitor usage.
- **Admin auth is password-only** — acceptable v1; rotate via env; no login audit trail.
- **Midnight boundary:** worker working past 23:59 local gets a new attendance day on check-out.
- **Serwist build tool mismatch:** verify SW file exists in deploy output; fall back to `@serwist/turbopack` if needed.
- Replace placeholder office coords/IP in env before go-live.

# Fix Auth.js “Server error” on Netlify (Google SSO)

## Problem

After Google SSO + Netlify env vars, sign-in shows:

> **Server error** — There is a problem with the server configuration. Check the server logs for more information.

This is Auth.js’s generic failure when it cannot start OAuth correctly.

## Root causes (most likely first)

| Cause | Why it breaks |
|-------|----------------|
| `AUTH_SECRET` missing/empty in **Functions** env | Auth.js requires it in production; throws this exact error |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` missing or empty at **runtime** | Provider cannot initialize |
| `AUTH_TRUST_HOST` not set | Netlify is a reverse proxy; Auth.js does **not** auto-trust Netlify (only Vercel / CF Pages). Wrong host → config/redirect failures |
| Env vars only set after deploy, **no redeploy** | Serverless functions don’t see new env until redeploy |
| Env scoped only to Builds, not Functions | Auth routes run as Netlify Functions |
| Google redirect URI mismatch | Often shows later; this specific “server configuration” error is usually env/secret first |

## Recommended fix (code)

### 1. Harden `lib/auth.ts`

- Set `trustHost: true` (required for Netlify).
- Read Google credentials with Auth.js inference **and** our current names:
  - `AUTH_GOOGLE_ID` / `AUTH_GOOGLE_SECRET` (preferred)
  - fallback `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`
- Read `AUTH_SECRET` (required); throw a **clear** error if missing in production.
- Optionally set `baseURL` from `AUTH_URL` when present.
- Keep JWT strategy + existing jwt/session callbacks.
- Do **not** log secret values.

Sketch:

```ts
const secret = process.env.AUTH_SECRET;
const clientId =
  process.env.AUTH_GOOGLE_ID || process.env.GOOGLE_CLIENT_ID;
const clientSecret =
  process.env.AUTH_GOOGLE_SECRET || process.env.GOOGLE_CLIENT_SECRET;

if (!secret) throw new Error("AUTH_SECRET is not set");
if (!clientId || !clientSecret) throw new Error("Google OAuth env is missing");

export const { handlers, auth, signIn, signOut } = NextAuth({
  providers: [Google({ clientId, clientSecret })],
  secret,
  trustHost: true,
  baseURL: process.env.AUTH_URL || undefined,
  session: { strategy: "jwt" },
  pages: { signIn: "/" },
  // ...existing callbacks
});
```

### 2. Safe diagnostics route

Add `GET /api/auth/debug` (dynamic) that returns **presence booleans only** (never values):

```json
{
  "hasAuthSecret": true,
  "hasGoogleClientId": true,
  "hasGoogleClientSecret": true,
  "hasAuthUrl": false,
  "trustHostEnv": "true"
}
```

Helps confirm Netlify Functions actually see the env vars.

### 3. Auth route hygiene

`app/api/auth/[...nextauth]/route.ts`:

```ts
export const runtime = "nodejs";
export const dynamic = "force-dynamic";
export const { GET, POST } = handlers;
```

### 4. Docs / env example

Update `.env.example` + README:

```
# Required on Netlify (Functions scope, all contexts you use)
AUTH_SECRET=<openssl rand -base64 32>
AUTH_GOOGLE_ID=<Client ID>
AUTH_GOOGLE_SECRET=<Client Secret>
# Strongly recommended on Netlify
AUTH_TRUST_HOST=true
AUTH_URL=https://YOUR-SITE.netlify.app
# Optional aliases still supported
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
```

Also list `ADMIN_EMAILS` and office vars as usual.

## Required Netlify operations (user)

1. Netlify → **Site settings → Environment variables**
2. Set for **Production** (and Deploy previews if you test there):
   - `AUTH_SECRET` — long random string (`openssl rand -base64 32`)
   - `AUTH_GOOGLE_ID` = Client ID (or keep `GOOGLE_CLIENT_ID`)
   - `AUTH_GOOGLE_SECRET` = Client secret (or keep `GOOGLE_CLIENT_SECRET`)
   - `AUTH_TRUST_HOST=true`
   - `AUTH_URL=https://YOUR-SITE.netlify.app`
   - `ADMIN_EMAILS=...`
3. Scope: available to **Functions** (default all scopes is fine).
4. **Redeploy** the site after saving env vars.
5. Google Console redirect URI must include:
   ```
   https://YOUR-SITE.netlify.app/api/auth/callback/google
   ```
6. If consent is Testing: add the test Google account as a **Test user**.

## Ops quick checklist (if still failing after code fix)

- [ ] `AUTH_SECRET` set and non-empty
- [ ] Google Client ID/Secret match Cloud Console
- [ ] `AUTH_TRUST_HOST=true`
- [ ] `AUTH_URL` matches production site URL (no trailing slash issues)
- [ ] Redeployed after env changes
- [ ] Redirect URI exact: `https://SITE.netlify.app/api/auth/callback/google`
- [ ] Google test users include the signing-in account (if Testing)
- [ ] Netlify Functions logs: look for Auth.js errors after clicking Sign in
